Configuration

Provider Android actif, modèle et paramètres généraux.

Application fournisseur

Un seul provider est actif. L’import ou le remplacement se fait dans l’application Android, serveur arrêté.

Paramètres

Comportement général du proxy (mode classique).

Streaming (SSE)
Autorise les réponses en flux. C'est le client qui choisit (stream: true ou en-tête Accept: text/event-stream) ; sans demande, la réponse est du JSON. Désactivé, un client qui demande un flux reçoit une erreur 400 explicite.
Auto-configuration
Non disponible sur Android : sélectionne le provider depuis l’application.
Nouvelle discussion à chaque requête
Non disponible sur Android actuellement. Ouvre un nouveau chat pour chaque requête : tout le contexte est renvoyé, sans empilement dans l'UI web. Désactivé par défaut (la discussion web persiste) ; une intégration d'agent active l'ignore de toute façon.
Markdown premium
Non disponible sur Android : la lecture suit la configuration du provider, notamment son bouton Copier.
Arrêter les jobs
Annule toutes les requêtes en attente ou en cours.
Tu utilises un agent de code (Qwen Code, Nemesis…) ? Active son intégration dans Intégration agents IA : une seule discussion web, un contexte géré, des appels d'outils natifs. Ces intégrations ignorent « Nouvelle discussion à chaque requête ».

L’API

Le proxy parle OpenAI. Rien d'autre.

Le corps de la requête est strictement OpenAI : model, messages, tools, stream. Aucune variable propriétaire (fresh_chat n'existe plus). L'agent se déclare par un en-tête HTTP, que tous les clients savent envoyer.
